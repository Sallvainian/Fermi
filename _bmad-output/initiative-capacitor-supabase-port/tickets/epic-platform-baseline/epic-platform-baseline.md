# The new app ships from CI

## Description

A Vite React web build lives in a new app/ folder beside the untouched Flutter app, with the app/src/api/ client and its error map (AD-17); a new deploy workflow replaces 02_deploy_web.yml and, on a push to main, applies Supabase migrations, pushes the hosted Auth config and sets Realtime private-only, deploys edge functions, builds, publishes updates/latest.json naming the build and its app/ id, deploys the fermi-plus Worker from an assets-only wrangler.jsonc on workers.dev, which replaces wrangler.toml and passes a health check that also asserts the Auth and Realtime config and the hosted site_url and redirect URLs pinned to the workers.dev origin, with sign-up off until epic 2's hook exists (AD-7, AD-21); the empty app and internal schemas, pg_cron, pg_net and pgtap, the job-health check the keep-alive calls, the job-failure table, the privilege fixture and its catalog test exist (AD-3); access-policy and edge-function tests run in CI; scheduled workflows keep the Free project awake and take a weekly encrypted backup (K18); Fermi saved to the Home Screen from Safari opens standalone as Fermi+ with its own icon; after a deploy that changed app/, an open Fermi still on the previous build is replaced by a full-screen refresh page that cannot be dismissed, which waits up to 2 minutes for an upload or CSV import in progress, and after Refresh what the user was typing comes back from the one draft store every later epic's content forms use (AD-24, AD-26); the iOS project, Capacitor and the native-build checks built before the owner dropped the iPhone app (2026-11-07) are gone; the dead Flutter-era workflows 01_ci, 03, 04 and 05 and the repo secrets only they use are removed, Dependabot covers app/ and GitHub Actions, the Main ruleset on the default branch requires test.yml's summary check and the dependency review before a merge, Dependabot pull requests merge themselves once both pass and go live within a day (AD-23), and the Claude workflows target app/ and supabase/. Every later epic builds on this pipeline.

## Outcome

Every later epic ships by pushing to main: the website on workers.dev updates with no hand deploy, an open Fermi whose app changed is refreshed onto it without losing what the user was typing, and the Free Supabase project stays awake and backed up (initiative K7, K18, R23).

## Requirements

- R1 (parent R23, AD-24, Decision 2026-11-07): after a deploy that changed `app/`, a Fermi tab or Home Screen web app still running the previous build is replaced by a full-screen page that cannot be dismissed, showing only "A new version of Fermi+ is ready. Refresh to keep using Fermi+." and one Refresh button; Fermi checks `updates/latest.json` when it opens, when it comes back on screen and every 15 minutes while on screen; a deploy that changed nothing under `app/` shows no page; Refresh loads the new build
- R2 (parent K7, AD-7, AD-21, AD-24, Decision 2026-11-07): a push to main runs, in order and with no hand step: migrations, the hosted Auth config push, Realtime private-only, edge functions, build and publishing `updates/latest.json` with the build's commit id and its `app/` id, `wrangler deploy`, and a health check that fails unless the site and `updates/latest.json` are served, `/` and `/updates/latest.json` with `max-age=0`, and the hosted config has email sign-in on, anonymous sign-ins off, sign-up off, Realtime private-only, and `site_url` and every redirect URL on `https://fermi-plus.sallvain.workers.dev`
- R3 (parent K6): the Worker `fermi-plus` on workers.dev (`fermi-plus.sallvain.workers.dev`) serves the web build as static assets only from `wrangler.jsonc`; `wrangler.toml`, `src/index.js` and `02_deploy_web.yml` are gone
- R4 (parent K1, Decision 2026-11-07): `app/` holds the Vite React web build only: no Capacitor package, `capacitor.config`, iOS project or `MIN_NATIVE_BUILD`, and no workflow, `test.yml` job or script refers to them; the Flutter app is untouched
- R5 (parent K13, AD-3): every pull request and push runs ESLint, typecheck, Vitest, pgTAP, `deno test` and Playwright (Desktop Chrome, iPhone WebKit), and any failure fails the run; a checked-in privilege fixture lists the expected grants for every table, column, function and view, and a pgTAP catalog test fails on any object missing from it or differing
- R6 (AD-17): `app/src/api/` is the only code that imports the Supabase client and maps every error key to text in one place; edge functions answer with the real HTTP status and `{ "error": { "code", "message" } }` through one shared helper

- R9 (parent K18, AD-21): a weekly workflow dumps the hosted database (roles, schema, data) through the Session pooler, encrypts it to the owner's age key, keeps it as a 90-day artifact never committed, and proves it by restoring into a throwaway local database

- R11 (Decision 2026-11-06, Decision 2026-11-07): Dependabot opens grouped weekly version-update pull requests for `app/`'s npm packages (vitest packages together, majors included; production and dev minor and patch grouped) and for GitHub Actions, and for nothing else, and its version-update jobs run without errors
- R12 (Decision 2026-11-06, AD-23, Decision 2026-11-07): Main, the default branch only, accepts a merge only after exactly two required checks pass, `Test Summary` (`test.yml`'s summary job) and `Dependency Review`, which fails at moderate severity; a Dependabot pull request merges itself once both pass; a merged Dependabot update is live on the site within a day with no hand step
- R13 (Decision 2026-11-06): `claude.yml` and `claude-code-review.yml` work on `app/` and `supabase/` with no Flutter setup, and no doc describes a removed workflow or secret
- R14 (parent R11, R25, Decision 2026-11-07): Fermi added to the Home Screen from Safari opens standalone, with no Safari bar, named Fermi+ and with Fermi's own icon, from a web app manifest the site serves; the iPhone web push of parent R11 needs it
- R15 (parent R23, AD-26, Decision 2026-11-07): what a signed-in user types into a form that creates or edits content is kept in that tab or Home Screen web app only (`sessionStorage`), on each change, and comes back on the same screen after the refresh page's Refresh; passwords and picked files are never kept; a draft is cleared when its content is sent, saved or cancelled, and every draft at sign-out
- R16 (parent R23, AD-24, Decision 2026-11-07): while an upload or a CSV import is in progress, the refresh page waits for it to finish, at most 2 minutes, so the refresh does not cut it off

## Constraints

- K1 (parent K1): one web codebase ships the website and the Home Screen web app; no Capacitor, iOS, Android or desktop shell
- K2 (parent K2): Supabase is the only backend; no Firebase SDK, config or project dependency in `app/`, `supabase/` or the new workflows
- K6 (parent K6): Cloudflare Workers static assets only, Worker `fermi-plus` on the free workers.dev subdomain `sallvain`, no bought domain, no Worker script
- K7 (parent K7): deploy order migrate, Auth config and Realtime private-only, edge functions, build and `latest.json`, wrangler deploy, health check; nothing is deployed by hand
- K13 (parent K13): access policies and edge functions have automated tests that run in CI
- Merge gate (AD-23): every check that must block a merge is a `test.yml` job that `Test Summary` waits on, added to it in the same change; `test.yml` reads no repo or environment secret and tests against the local stack only
- K18 (parent K18): Supabase Free plan; keep-alive twice daily; weekly backup encrypted to the owner's key, never committed, because the repo is public; Storage bytes are not backed up
- Stack (spine Stack, Deferred): the Stack table's versions are pinned; Supabase CLI 2.122.0, as in My-Love's workflows

## Done when

- A push to main runs migrations, the Auth config push, the Realtime private-only setting, edge functions, build, `latest.json`, wrangler deploy and a health check that asserts the hosted config, `site_url` and redirect URLs on the workers.dev origin included, with no hand step
- The workers.dev site serves the web build from an assets-only `wrangler.jsonc`, and `wrangler.toml`, `src/index.js`, `02_deploy_web.yml` and the Flutter-era root `package.json` are gone
- Access-policy, privilege-fixture and edge-function tests run in CI and fail the run when they fail
- The keep-alive and weekly backup workflows run on schedule, and the backup restores into a throwaway local database
- After the next deploy that changes `app/`, an open Fermi on the previous build, in a tab and saved to an iPhone's Home Screen, shows only the refresh page on returning to the screen or within 15 minutes, and after Refresh shows the new commit id; a deploy that changes nothing under `app/` shows no page
- A value kept through the draft store is back after Refresh, and the refresh page waits while the busy registry holds work, at most 2 minutes
- Fermi saved to the owner's iPhone Home Screen from Safari opens standalone as Fermi+ with Fermi's icon
- `app/` holds no Capacitor package, iOS project or `MIN_NATIVE_BUILD`, and no workflow, `test.yml` job or script refers to them
- Workflows 01_ci, 03, 04 and 05 are gone, and `gh secret list` shows none of the ten secrets only they used and no repo-level Cloudflare secret
- Dependabot's version-update jobs for `app/` npm and GitHub Actions run without errors; Main refuses a merge while `Test Summary` or `Dependency Review` is red; a Dependabot pull request merges itself once both are green and is live within a day
- The Claude workflows install no Flutter and target `app/` and `supabase/`
- A `bmad-tea-trace` run at closure maps R1–R16 to passing tests or each story's runnable check, and its gate is PASS or each gap has a waiver in Notes
